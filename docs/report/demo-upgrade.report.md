## 단계별 완료 내역

### 08단계: OpenAI → Google Gemini 전환 (2026-10-06, `d34b7ce4`)
- LLM `gpt-4o-mini` → `gemini-3.5-flash-lite`, 임베딩 → `gemini-embedding-001`(768차원)
- 무료 임베딩 한도(분당 100·하루 1,000회) 때문에 벡터 DB를 **미리 만들어 커밋**하는 구조로 변경 (결정 001·002)
- 문서 분할 줄바꿈 버그, `requirements.txt` UTF-16 인코딩, `venv/` 커밋 정리

### 09단계: 파일 정리와 음성 버그 수정 (2026-10-07, `d05e5443`, `40f20ddb`)
- 불필요한 파일 정리, FastAPI 버전 제거, README 작성
- 음성 오버레이가 안 닫히고 취소가 안 되던 문제(iframe 재생성), 한 문장이 여러 번 전송되던 문제 수정 (결정 003)

### 10단계: 데모 고도화 (2026-10-07 야간~오전, 브랜치 `10-demo-upgrade`)
- **기록 체계**: `docs/`(기획서, 개발 일지, 결정 기록, 평가, 교육 자료 목차), `CHANGELOG.md`
- **평가 세트**: 질문 20개 + 정답 페이지, `eval/run_eval.py` (Hit@k, MRR) — 정답 범위를 섹션 전체로 보정 (70% → 90%)
- **음성 개편**: Web Speech API → `st.chat_input(accept_audio=True)` + Gemini 받아쓰기 + 차량 용어 힌트 (결정 004) — TTS 10/10, 힌트 없음 6/10
- **답변 품질**: 참고 페이지 표시, 스트리밍, 예시 질문, 수치를 그대로 제시하는 프롬프트
- **안정성**: 임베딩 429 시 키워드(BM25) 검색 자동 전환, 한국어 오류 안내(`errors.py`), 패키지 버전 고정
- **코드 구조**: 734줄 단일 파일 → 모듈 분리 (settings / retrieval / agent / voice / errors)
- **코드 리뷰 10건 반영**: 예시 질문 재전송 루프, 공백 답변, 오류 분류 통합, TTS 명령 주입 방지 등
- **갭 분석**(`/pdca analyze`): 구현 94.6% / 검증 53.6% → G1·G4 조치
- **사용자 결정**: 005 새로고침 시 대화 저장 안 함, 006 음성 질문 바로 전송 + "음성 질문" 표시

### 11단계: 답변 속도 개선 (`e0b3417d`, 결정 007)
- Agent(모델 2~3회 호출) → RAG 체인(검색 먼저 + 모델 1회), 답변 간결화, 진행 단계 표시
- 첫 글자 3.10s → **1.81s (−42%)**, 답변 완료 6.08s → **3.90s (−36%)**
- 이어지는 질문("그럼 냉각수는?")은 직전 질문과 합쳐 검색
- 남은 25조각 임베딩 완료(**1,005/1,005**), 벡터 검색 **Hit@3 100%(20/20), MRR 0.94**

### 12단계: '개발 과정 보기' 팝업 (`7f5b4545`)
- 제목 아래 작은 링크 → 팝업: 작동 원리 순서도, 개발 여정(문제→해결 표), 개선 효과(전후 비교 숫자 타일)

### 13단계: 임베딩 원리·AI 설정(페르소나) 탭 (`e6d7f0f7`)
- **임베딩 원리**: 매뉴얼 단어를 피한 질문 6개 × 주제별 매뉴얼 조각 6개의 **유사도 히트맵**(대각선 0.70~0.76, 나머지 0.49~0.65), 키워드 vs 임베딩 비교, **직접 해 보기**(질문 1개를 1,005조각과 비교해 상위 3개 + 키워드 검색 결과)
- **AI 설정·페르소나**: `settings.py`의 시스템 프롬프트를 그대로 표시, 규칙별 이유, 전달 구조, 설정값
- 2차원 압축 산점도는 질문/문서 임베딩 차이 때문에 오해를 불러 히트맵으로 변경

## 주요 문제와 배운 점

### 발견한 문제와 해결 (교육 자료 사례)

1. **무료 API 한도 설계의 중요성**: 새 프로젝트인데도 하루 임베딩 한도 1,000회 초과 → 한도가 바닥났을 때 앱이 동작하는 방식(키워드 대체)을 설계에 포함해야 함

2. **평가 기준의 영향**: 정답 페이지 범위가 좁으면 검색 품질이 낮게 평가됨(Hit@3 70%) → 실패 사례를 직접 열어보고 범위 조정(Hit@3 90%)

3. **라이브러리 가설 검증**: "한도 초과로 재시도한다"는 가설도 코드 확인으로 거짓임을 알 수 있음

4. **Streamlit 위젯 상태 관리**: `st.chat_input` 값을 생성 후 수정하면 오류 → AppTest로 발견하고 입력 전에 값 주입으로 해결

5. **배포 전 체크리스트**: 한글 주석 때문에 Windows에서 `pip install` 실패(cp949 인코딩) → 빈 환경 설치 테스트를 필수 항목으로 추가

6. **벡터 DB 파일 관리**: Chroma DB는 열기만 해도 파일을 수정해 git에 "변경됨"으로 보임 → 브랜치 전환 전에 앱 종료, 필요시 `git reset --mixed`로 마스터만 이동

7. **UI 시각화의 정직성**: 2D 압축 그림이 메시지와 다르게 보이면 그림을 고치기보다 **데이터를 정직하게 보여주는 형태**로 변경(실제 유사도 히트맵)

8. **재현 코드의 가치**: 공식 가이드도 그대로 믿지 말고 작은 재현 코드로 직접 확인

6. **팝업 교육 콘텐츠**: 임베딩 원리(벡터 유사도 히트맵), 페르소나(시스템 프롬프트)
