# 007. 답변 속도를 위해 Agent 대신 RAG 체인(검색 먼저 + 모델 1회)

- **날짜**: 2026-10-07
- **상태**: 채택

## 배경
로컬과 배포 링크 모두에서 "답변이 오래 걸린다"는 의견. `eval/timing.py`로 측정한 결과,
LangChain `create_agent` 구조가 질문 1개에 모델을 **2~3번 차례로 호출**하고 있었다.

```
질문 → ① 모델: "검색할지" 판단(1.0~1.4초) → ② 검색(0.5초) → (가끔 ①② 반복: 재검색) → ③ 모델: 답변 작성
```

검색 자체(0.5초)는 빠르고, 시간은 ①·재검색·긴 답변에서 쓰였다. 한도 초과 재시도는 원인이 아니었다
(임베딩·답변 모델 모두 재시도 없이 바로 실패하도록 되어 있음을 라이브러리 코드로 확인).

## 선택지
| 선택지 | 장점 | 단점 |
|---|---|---|
| Agent 유지 | 검색이 필요 없는 질문(인사 등)에 유연 | 매 질문 모델 호출 2~3회 |
| **A. RAG 체인: 검색 먼저 → 모델 1회** | 판단 단계·재검색 제거 | 이어지는 질문은 검색어 보완 필요 |
| B. 답변 길이 제한 | 완료 시간 단축 | 상세 절차가 잘릴 위험 |
| C. 진행 단계 표시 | 체감 대기 감소 | 실제 시간은 그대로 |

## 결정
A + B + C 모두 적용.
- A: `agent.Assistant.search()` → `stream()`. "그럼 냉각수는?"처럼 짧거나 '그럼/그건…'으로 시작하는 질문은 직전 질문과 합쳐서 검색
- B: 프롬프트에 "10줄 이내, 반복·인사말 없이", `max_output_tokens=1024`, `thinking_level="minimal"`
  (`thinking_budget=0`은 이 모델에서 400 INVALID_ARGUMENT라 사용 불가 — 실제 호출로 확인)
- C: `st.status`로 "매뉴얼 검색 중 → 검색 완료(○쪽) · 답변 작성 중" 표시

## 결과 (같은 질문 4개, 로컬)
| | 첫 글자 | 답변 완료 | 모델 호출 |
|---|:-:|:-:|:-:|
| 개선 전 (Agent) | 3.10초 | 6.08초 | 2~3회 |
| **개선 후 (RAG 체인)** | **1.81초 (−42%)** | **3.90초 (−36%)** | **1회** |

- 기록: `docs/eval/2026-10-07_latency_before.md`, `docs/eval/2026-10-07_latency_after.md`
- 품질: 벡터 검색 Hit@3 **100%**(20/20), MRR 0.94. 이어지는 질문("그럼 냉각수는?") 정답(8.6ℓ/9.7ℓ/1.48ℓ) 확인

## 영향
- 질문당 모델 호출이 1회로 줄어 **무료 한도(분당 15회) 여유도 2~3배** 늘었다.
- 검색이 필요 없는 잡담도 항상 검색한다 (매뉴얼 챗봇이라 문제없음).
- 이어지는 질문 판별은 단순 규칙(길이·시작 단어)이라, 길게 쓴 이어지는 질문은 직전 질문 없이 검색될 수 있다.

## 남은 대기 시간 (줄일 수 없는 부분)
검색 왕복 약 0.5초 + 모델 첫 글자 약 1초 + 답변 길이에 비례한 작성 시간.
배포 앱은 무료 요금제 특성상 오래 안 쓰면 잠들어 첫 접속에 수십 초가 걸린다 → 시연 5~10분 전에 미리 열어 두기.
