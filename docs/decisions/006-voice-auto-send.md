# 006. 음성 질문은 바로 전송하고, 받아쓴 문장을 말풍선에 표시

- **날짜**: 2026-10-07
- **상태**: 채택 (004의 "확인 후 전송 기본값"을 변경)

## 배경
004에서는 받아쓴 문장을 입력창에 넣고 사용자가 확인한 뒤 전송하게 했다(시연 중 오인식 대비).
PC 실사용 테스트에서 받아쓰기가 정확했고, 시연에서는 "말하면 답이 나온다"는 흐름이
중요한데 전송을 한 번 더 눌러야 해 흐름이 끊긴다는 의견이 나왔다.

## 선택지
| 선택지 | 장점 | 단점 |
|---|---|---|
| 확인 후 전송 (기존) | 오인식을 보내기 전에 고칠 수 있음 | 클릭이 한 번 더 필요, 시연 흐름이 끊김 |
| 바로 전송, 받아쓴 문장 숨김 | 가장 매끄러움 | AI가 무엇을 알아들었는지 보이지 않아 신뢰·교육 효과 감소 |
| **바로 전송 + 받아쓴 문장을 "음성 질문"으로 표시** | 매끄럽고, 알아들은 내용이 보임 | 오인식된 질문이 그대로 전송될 수 있음(한도 소모) |

## 결정
기본값을 바로 전송(`settings.VOICE_AUTO_SEND = True`)으로 바꾸고, 사용자 말풍선에
":material/mic: 음성 질문 (받아쓴 문장)" 표시를 붙인다. 확인 후 전송은 사이드바 "대화 관리"의
"받아쓴 문장 바로 전송" 토글을 끄면 쓸 수 있다.

## 이유
- PC 실사용 테스트에서 받아쓰기가 정확했다 (TTS 평가에서도 용어 힌트 10/10).
- 받아쓴 문장이 그대로 보이므로 "AI는 이렇게 알아들었다"를 시연·교육에서 짚을 수 있다.
- 정확한 질문이 중요한 수업에서는 토글로 확인 모드를 켤 수 있어 기존 장점도 유지된다.

## 검증
`tests/test_app.py` — 녹음 제출을 재현(AppTest는 녹음 제출을 지원하지 않아 입력창·받아쓰기를 바꿔 끼움):
- 바로 전송: 받아쓴 문장이 `voice: True`로 기록, "음성 질문" 표시, 답변 생성
- 확인 모드: 전송되지 않고 입력창에 받아쓴 문장이 들어감

## 다시 검토할 조건
- 모바일·실제 시연에서 오인식이 잦으면 확인 모드를 기본값으로 되돌린다.
