# 002. 벡터 DB를 미리 생성해 git에 커밋

- **날짜**: 2026-10-06
- **상태**: 채택

## 배경
기존 앱은 시작할 때마다 PDF 767페이지(1,005개 청크)를 임베딩해 메모리 Chroma에 넣었다.
Gemini 무료 티어 임베딩 한도(분당 100회, 하루 1,000회)를 넘어 429 오류로 앱이 뜨지 않았다.

## 선택지
| 선택지 | 장점 | 단점 |
|---|---|---|
| 앱 시작 시 천천히 임베딩 (재시도/지연) | 구조 변경 적음 | 시작에 10분 이상, 재시작마다 한도 소모 |
| **로컬에서 1회 생성 후 커밋** | 앱 시작 즉시, 한도 소모 없음 | PDF 변경 시 재생성·재커밋 필요 |
| 외부 벡터 DB 서비스 | 확장성 | 실습 데모에는 과함, 계정·비용 추가 |

## 결정
`build_vectorstore.py`로 `chroma_db/`를 만들어 커밋하고, 앱은 `Chroma(persist_directory=...)`로 로드만 한다.
공통 설정은 `vectorstore_config.py`에 둔다.

## 이유
- 매뉴얼은 거의 바뀌지 않는다 → 한 번 만들면 끝.
- 배치 지연(분당 80회)과 이어하기(청크 ID 기준)로 한도 안에서 안전하게 생성 가능.
- 768차원 기준 DB 약 16MB로 git에 올려도 부담이 작다.

## 영향
- `chromadb` 버전을 고정해야 한다 (DB 파일 형식 호환).
- PDF나 분할 설정을 바꾸면 `chroma_db/`를 지우고 다시 생성해야 한다.
- 질문할 때는 질문 문장 1개만 임베딩한다 (질문당 1~3회).
