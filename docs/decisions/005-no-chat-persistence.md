# 005. 새로고침 시 대화를 저장하지 않음 (현행 유지)

- **날짜**: 2026-10-07
- **상태**: 채택

## 배경
새로고침하면 이전 대화가 모두 사라진다. Streamlit은 브라우저 탭마다 세션을 만들고
`st.session_state`에 대화를 두기 때문에, 새로고침하면 새 세션이 시작된다(버그가 아닌 기본 동작).

## 선택지
| 선택지 | 장점 | 단점 |
|---|---|---|
| **현행 유지** | 시연마다 깨끗하게 시작, 여러 사람이 같은 링크를 써도 대화가 섞이지 않음, 저장·개인정보 관리 불필요 | 실수로 새로고침하면 대화가 사라짐 |
| A. 서버 메모리 + 주소에 대화 ID(`?chat=...`) | 약 20줄로 구현, 새로고침 후 복원 | 서버 재시작(Cloud 슬립) 시 사라짐, 주소를 공유하면 대화 노출 |
| B. 서버 파일(SQLite) 저장 | 로컬에서는 재시작 후에도 유지 | Streamlit Cloud는 재배포·재부팅 시 파일 삭제, 개인정보 관리 부담 |
| C. 브라우저 localStorage | 기기별 유지 | 커스텀 JS 컴포넌트 필요 → 004에서 걷어낸 JS 의존 구조로 회귀 |

## 결정
현행 유지. 기획서의 "범위 밖(사용자별 대화 저장)"을 그대로 둔다.

## 이유
- 실습용 데모는 시연마다 처음부터 보여 주는 경우가 많아, 저장보다 깨끗한 시작이 더 유용하다.
- 저장을 넣으면 "어디에·얼마 동안·누가 볼 수 있게"를 정해야 해 데모 목적에 비해 부담이 크다.
- 대화 초기화가 필요하면 사이드바 "대화 내용 지우기"로 충분하다.

## 다시 검토할 조건
- 수업 중 새로고침으로 대화가 끊겨 불편이 반복될 때 → A안(서버 메모리 + 대화 ID)부터 검토
- 로그인 기능을 넣게 될 때 → 사용자별 저장(B안 이상) 검토
