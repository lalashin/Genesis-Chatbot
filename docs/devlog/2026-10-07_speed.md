## 문제와 해결

### 1. "한도 초과 시 라이브러리가 몰래 재시도해서 느린 것"이라는 가설 → 아님
- 기본값 `max_retries=6`을 보고 의심했지만, 라이브러리 코드를 따라가 보니 임베딩은 재시도 옵션을 SDK에 넘기지 않아 재시도 없음, 답변 모델은 우리가 `max_retries=1`로 둠
- **배운 점**: 그럴듯한 가설도 코드나 측정으로 확인하기 전에는 원인이라고 말하지 않는다

### 2. `thinking_budget=0` → 400 INVALID_ARGUMENT
- 생각하기 단계를 끄려고 넣었는데 Gemini 3.x flash-lite는 거부
- 실제 호출로 비교: 기본 / `thinking_level=minimal` / `low` 모두 동작, 차이는 1초 이내 → `minimal` 채택

### 3. 답변이 "핵심 답:"으로 시작
- 프롬프트 "핵심 답을 첫 문장에 먼저 말하세요"를 머리말로 그대로 출력 → "첫 문장에서 바로 답하고 머리말을 붙이지 말라"로 수정

### 4. 이어지는 질문
- Agent는 모델이 검색어를 다시 썼지만 체인은 질문을 그대로 검색 → "그럼 냉각수는?"만으로는 엉뚱한 페이지
- 짧거나 '그럼/그건…'으로 시작하면 직전 질문과 합쳐 검색 → 23쪽(추천 오일 및 용량) 찾고 정답 확인

### 5. 배포하려다 브랜치 전환 실패: `unable to unlink old 'chroma_db/...'`
- **증상**: master로 전환·병합하는 중 DB 파일 5개를 교체하지 못하고 중단 (push도 안 됨)
- **원인**: 로컬에서 실행 중인 Streamlit 앱이 `chroma_db/` 파일을 열어 둔 상태(Windows는 열린 파일 삭제 불가). Ctrl+C 후에도 "Shutting down"에서 멈춘 프로세스 3개가 남아 계속 잠금
- **해결**: 잠긴 파일을 건드리지 않고 `git reset --mixed <새 커밋>`으로 master만 이동 → 나머지 파일 복원 → push. 다음 배포부터는 `git push origin <브랜치>:master`로 브랜치 전환 없이 배포. 남은 프로세스 종료 후 `git checkout -- chroma_db`로 로컬 복원
- **추가 발견**: Chroma는 DB를 **열기만 해도** `chroma.sqlite3`를 고쳐 써서 git에 "변경됨"으로 보인다 (데이터 문제 아님). 커밋 전에 `git checkout -- chroma_db`로 되돌리면 됨
- **배운 점**: 벡터 DB처럼 커밋하는 바이너리 파일이 있으면, 브랜치 전환·병합 전에 그 파일을 쓰는 앱을 모두 끈다
