# 강의 활용 가이드: GENESIS AI Assistant

> 이 데모를 나중에 강의·특강·워크숍 자료로 쓸 때 **어디서부터 시작하면 되는지** 정리한 지도입니다.
> 아직 강의안은 아닙니다. 대상과 시간이 정해지면 이 가이드를 출발점으로 강의안을 만듭니다(맨 아래 "강의안으로 만들 때").
>
> 작성: 2026-10-07 · 기준 코드: 태그 `v13-theory-tabs` · 배포: https://genesis-chatbot.streamlit.app/

---

## 1. 이 데모가 교재로 좋은 이유

1. **같은 챗봇의 "처음 버전"과 "다듬은 버전"이 모두 남아 있습니다.**
   AI 채팅만으로 만든 버전(`v07`)과, 문제를 하나씩 찾아 고친 버전(`v13`)을 나란히 보여 줄 수 있습니다.
2. **실패가 기록되어 있습니다.** 오류 메시지, 원인을 찾은 방법, 해결, 배운 점이 개발 일지에 남아 있습니다.
   잘 된 결과보다 **실패 사례가 더 좋은 수업 소재**입니다.
3. **모든 개선이 숫자로 증명됩니다.** 받아쓰기 6→10/10, 검색 Hit@3 90→100%, 첫 글자 3.1→1.8초.
4. **앱 안에 설명 화면이 있습니다.** 제목 아래 "개발 과정 보기"로 구조·임베딩·페르소나·개발 여정·개선 효과를 바로 보여 줄 수 있습니다.

## 2. 가르칠 수 있는 주제

| 주제 | 핵심 메시지 | 보여 줄 자료 |
|---|---|---|
| **RAG 기본** | "AI가 외워서 답하는 게 아니라, 매뉴얼을 찾아 읽고 답한다" | 앱 > 개발 과정 보기 > 작동 원리, `agent.py` |
| **임베딩** | 문장의 뜻을 숫자 768개로 → 단어가 달라도 뜻으로 찾는다 | 개발 과정 보기 > 임베딩 원리 (히트맵, 직접 해 보기) |
| **데이터 준비(청킹)** | 나누는 방식이 품질을 좌우한다 | `build_vectorstore.py`, 줄바꿈 버그 사례 |
| **검색 품질 평가** | "잘 된다"를 숫자로 증명한다. 평가 기준이 결과를 좌우한다 | `eval/questions.json`, `eval/run_eval.py`, 70→90% 사례 |
| **프롬프트·페르소나** | AI에게 역할과 규칙을 주면 답이 달라진다 | 개발 과정 보기 > AI 설정·페르소나, `settings.py` |
| **Agent vs RAG 체인** | 유연성과 속도의 트레이드오프 | 결정 007, 속도 측정 전후 |
| **음성 인터페이스** | 범용 음성인식은 전문 용어를 틀린다 → 맥락을 주면 정확해진다 | "차체→자체" 사례, `voice.py`, 결정 004 |
| **무료 API로 서비스 운영** | 한도는 설계 조건이다 | 결정 002, 키워드 대체 검색, 429 안내 |
| **바이브 코딩의 함정과 검증** | AI가 만든 코드는 그럴듯해 보여도 검증이 필요하다 | 2025-12 회고 일지, 코드 리뷰 10건 |
| **배포** | 코드 밖에서도 깨진다 (인코딩, 권한, 파일 잠금) | 배포 전 체크리스트 (5장) |

## 3. 상황별 활용 방법

### A. 30분 시연 (발표·소개)
| 시간 | 내용 | 자료 |
|---|---|---|
| 5분 | 문제 소개: "767쪽 매뉴얼에서 필요한 답을 바로 찾고 싶다" | 앱 첫 화면 |
| 10분 | **라이브 시연** (4장 대본) | 배포 앱 |
| 10분 | 어떻게 만들었나: 작동 원리 → 임베딩 원리 | 개발 과정 보기 |
| 5분 | 개선 효과와 배운 점 | 개발 과정 보기 > 개선 효과 |

### B. 2시간 특강 (개념 + 시연)
1. RAG가 왜 필요한가 (20분) — LLM만 쓸 때의 한계(지어내기) vs 매뉴얼 근거 답변
2. 임베딩과 벡터 검색 (30분) — 히트맵, "직접 해 보기"로 청중 질문 받아 즉석 시연
3. 페르소나와 프롬프트 설계 (20분) — 시스템 프롬프트 규칙별 "없으면 생기는 일"
4. 품질을 숫자로 증명하기 (20분) — 평가 세트, 정답 기준 사례(70→90%)
5. 실패에서 배운 것 (20분) — 사례 3~4개 골라서 (6장)
6. 질의응답 (10분)

### C. 하루 워크숍 (따라 만들기, 6~8시간)
| 순서 | 실습 | 시작 코드 |
|---|---|---|
| 1 | 환경 준비, Gemini API 키 발급 | — |
| 2 | PDF → 청킹 → 임베딩 → 벡터 DB 만들기 | `v08-gemini`의 `build_vectorstore.py` |
| 3 | 검색해 보기 + 평가 세트로 Hit@3 측정 | `v10-demo-upgrade`의 `eval/` |
| 4 | 검색 결과로 답하는 챗봇 (RAG 체인) | `v11-speed` |
| 5 | 페르소나 바꿔 보기 실험 | `settings.py` |
| 6 | Streamlit Cloud 배포 | 5장 체크리스트 |

### D. 여러 날 과정 (프로젝트 기반)
수강생이 **각자 다른 문서**(제품 매뉴얼, 사내 규정 등)로 같은 구조의 챗봇을 만드는 형태.
이 데모는 "완성 예시"와 "단계별 참고 코드(태그)"로 씁니다. → 7장 "강의안으로 만들 때"

## 4. 시연 대본 (10분)

> 시연 **5~10분 전**에 배포 앱을 한 번 열어 두세요 (무료 앱은 오래 안 쓰면 잠들어 첫 접속에 수십 초).

1. **첫 화면** — "제네시스 차량 매뉴얼 767쪽을 읽고 답하는 AI입니다."
2. **예시 질문** "타이어 공기압" 클릭 → "매뉴얼 검색 완료(18쪽…) · 답변 작성 중" 표시를 짚으며
   "먼저 매뉴얼에서 찾고, 찾은 내용으로만 답합니다. 아래에 참고한 페이지가 나옵니다."
3. **이어지는 질문** "그럼 냉각수는?" → "앞 대화를 기억합니다."
4. **음성 질문** 🎙 "차체에 흠집이 났을 때 관리 방법" → 받아쓴 문장이 "음성 질문"으로 표시됨
   "범용 음성인식은 '자체'로 알아들었는데, 차량 용어를 알려 줬더니 정확해졌습니다."
5. **개발 과정 보기 > 임베딩 원리 > 직접 해 보기** → 청중에게 질문을 받아 입력
   (예: "엔진이 너무 뜨거워졌어") → "'과열'이라는 단어가 없어도 엔진 과열 페이지를 찾습니다."
6. **개선 효과** 탭으로 마무리 — "모든 개선은 측정해서 확인했습니다."

**시연 중 문제가 생기면**
| 증상 | 대처 |
|---|---|
| "질문이 몰려 잠시 쉬어가는 중" | 답변 모델 분당 한도(15회). 30초 뒤 다시. 시연 중 연속 질문은 4~5개까지 |
| 출처에 "· 키워드 검색" 표시 | 임베딩 하루 한도 초과로 대체 검색 중. 오히려 "한도 대비 설계" 설명 기회 |
| 음성이 이상하게 받아써짐 | 사이드바 > 대화 관리 > "받아쓴 문장 바로 전송" 끄기 → 확인 후 전송 |

## 5. 강의·시연 전 체크리스트

**하루 전**
- [ ] 배포 앱 접속해 텍스트·음성 질문 1회씩 확인
- [ ] **모델 이름이 아직 유효한지** — Gemini 모델은 자주 바뀝니다. 404가 나면 `settings.py`의 `LLM_MODEL` 교체 (결정 001)
- [ ] Streamlit Cloud > Secrets의 `GOOGLE_API_KEY` 유효 확인
- [ ] 수치(한도, 정확도, 속도)를 슬라이드에 쓴다면 **다시 측정**: `eval/run_eval.py`, `eval/timing.py`

**직전**
- [ ] 앱 미리 열어 깨우기 (5~10분 전)
- [ ] 마이크 권한 허용 확인 (시연 기기·브라우저)
- [ ] 연습 질문 수를 줄여 한도 아끼기

**실습(워크숍)이라면**
- [ ] 수강생 API 키는 **각자 발급** (한도가 프로젝트 단위라 한 키를 나눠 쓰면 금방 바닥남)
- [ ] 벡터 DB를 수강생이 직접 만들게 할지, 완성본(`chroma_db/`)을 줄지 결정 (만들기는 무료 한도로 10분 이상 + 하루 1,000회 제한)
- [ ] Windows 수강생: `requirements.txt`는 ASCII만 (한글 주석이 있으면 pip 오류)

## 8. 강의안으로 만들 때 (나중에)

1. **정하기**: 대상(비전공자/개발자), 총 시간, 형식(강의/실습), 수강생이 만들 결과물
2. **설계**: Claude Code의 `pbl-curriculum-design` 스킬로 차시·시수·미션·체크포인트 설계
   (출발점: `docs/lessons/README.md`의 9차시 목차 초안)
3. **본문 작성**: 차시마다 `docs/templates/lesson.md` 틀로 작성. 재료는 이 가이드 6장(사례)과 7장(태그)
4. **최신화**: 모델 이름·한도·Streamlit 버전을 다시 확인하고, 평가·속도 수치를 다시 측정
5. **리허설**: 4장 대본으로 시연 + 5장 체크리스트
